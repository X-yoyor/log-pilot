# LogPilot 首次使用手册

> 内网日志采集与智能分析平台 · 运维操作指南
> 适用版本：LogPilot v1.0 · 适用对象：运维工程师 / 后端工程师 · 文档版本：2026-10-27

本手册面向首次接触 LogPilot 平台的运维与后端同学，覆盖启动验证、接入内网日志、日常巡检与排障的完整路径。阅读第二章至第三章即可完成基本接入，其余章节可在实际使用中按需查阅。

（同内容 Word 版：[LogPilot-首次使用手册.docx](LogPilot-首次使用手册.docx) / [LogPilot-首次使用手册.pdf](LogPilot-首次使用手册.pdf)）

## 1. 平台简介与核心概念

LogPilot（日志护航）是部署在内网的单机日志采集与智能分析平台。它通过 SSH/SFTP 或本机文件方式定时增量采集各业务服务器上的日志文件，自动识别其中的异常报错与堆栈，把同类异常聚合成组，并结合内置知识库与可选的大模型能力给出原因分析和修复建议，最终通过告警与修复闭环帮助团队持续消除系统缺陷。

平台不采用 Agent 模式，被采集服务器上无需安装任何程序，只需提供一个具备日志文件读取权限的 SSH 账号即可，对业务系统零侵入。

| 概念 | 含义 |
|---|---|
| 服务器 | 被采集的目标机器。支持 SSH 远程服务器（密码或私钥认证）与 LOCAL 本机两种类型，凭据加密存储 |
| 日志源 | 一条采集配置：某台服务器上的一组日志文件路径，支持通配符、目录、单文件三种写法 |
| 异常事件 | 从日志中解析出的一条条异常报错记录，是原始粒度 |
| 异常组 | 由指纹算法把相同根因的异常事件聚合成的一类问题，平台围绕它做分析与修复管理 |
| 知识库 | 内置 31 条常见 Java 异常的原因与修复建议，也支持自定义正则规则扩展 |
| 告警 | 当窗口期内异常数量超过阈值时，通过 Webhook 或邮件发出通知 |
| 静默窗口 | 发布或处理故障期间，对指定日志源或异常组暂停告警，避免轰炸 |

## 2. 启动与首次访问

### 2.1 环境要求与启动方式

平台基于 Java 17 与内嵌 H2 数据库构建，服务器只需安装 JDK 17 及以上版本，无需外部数据库。源码目录 log-pilot 下执行 `mvn package -DskipTests` 完成打包，随后执行 `java -jar target/log-pilot.jar` 启动，默认端口为 18090。若端口被占用，可追加参数 `--server.port=8080` 换端口启动。

### 2.2 首次启动会发生什么

首次启动时平台会自动完成三件事：其一，写入 31 条内置异常知识规则与默认系统设置；其二，创建一组演示数据，包含一个本机节点和指向 demo-logs/app-demo.log 的演示日志源，日志文件里预置了空指针、数据库死锁、连接拒绝、超时等典型异常；其三，启动约 15 秒后自动执行首次采集。因此首次访问仪表盘时通常已能看到异常数据，方便直观了解平台的使用效果。

确认功能正常后，建议进入日志源页面删除演示日志源，再按第三章接入真实业务日志。

### 2.3 访问地址与数据位置

浏览器打开 http://服务器IP:18090 即可使用。平台当前未内置登录鉴权，请勿暴露到公网，建议仅在内网或通过带认证的反向代理访问。数据库为运行目录下的 data 文件夹（H2），Web 控制台位于 /h2-console（用户 sa，密码为空），可用于数据核查与备份前的检查。

## 3. 快速上手五步走

本章带你在十分钟内完成从零到收到第一条告警的完整配置，全程只在网页界面操作。

### 3.1 第一步：添加服务器

进入服务器页面，点击添加服务器。采集内网机器日志时选择 SSH 类型，填写名称、主机地址、端口（默认 22）、用户名与认证方式：密码认证直接填写密码；私钥认证粘贴 PEM 格式私钥，私钥口令填在密码框。若只是采集平台所在机器的日志，选择 LOCAL 本机类型即可。

1. SSH 账号需对目标日志目录具备读取权限，推荐使用专门的采集账号而非 root；
2. 保存后点击测试按钮验证连通性，成功会显示耗时毫秒数，失败会给出中文原因提示；
3. 服务器删除有保护：仍被日志源引用的服务器无法删除，需先删除或调整其下的日志源。

### 3.2 第二步：添加日志源

进入日志源页面，点击添加日志源。选择采集模式（SSH 或 LOCAL）、关联服务器，然后填写日志路径。路径支持三种写法：通配符（如 /var/log/myapp/*.log）、具体文件（如 /app/logs/error.log）、目录（采集其下所有 .log 文件）。Windows 路径同样支持，例如 D:/logs/app/*.log。

解析格式保持 AUTO 即可，平台会自动识别标准日志格式并合并多行堆栈；格式特殊时可改用 RAW 逐行模式。编码需与日志文件实际编码一致（UTF-8 或 GBK），否则中文会乱码。采集间隔默认 5 分钟，最小 1 分钟。保存后点击采集按钮可立即执行一次。

### 3.3 第三步：查看异常分析

采集完成后进入异常分析页面。同类异常已按指纹自动聚合：异常类名、归一化消息模板（订单号、IP 等可变内容已替换为占位符）与顶层业务堆栈帧三者一致的异常归为一组。点击任意一行进入详情页，可查看脱敏后的消息模板、原始堆栈、内置修复建议，并可执行 AI 根因分析、指派处理人、更新处理状态。

### 3.4 第四步：配置告警渠道与规则

先在告警页面的通知渠道标签下创建渠道：Webhook 类型填写接收地址（可对接企业微信、钉钉、飞书机器人网关），EMAIL 类型填写收件人。渠道是地址字典，供多条规则引用，后续更换地址只需改一处。创建后点击测试按钮验证连通。

再在告警规则标签下添加规则：指标可选窗口内异常事件数或窗口内新增异常类型，设置阈值、统计窗口与冷却时间（冷却期内不重复通知），日志源范围可限定单个源或全局，通知渠道选择刚创建的渠道。规则触发后写入触发记录，包含每次通知的渠道、状态与详情。

### 3.5 第五步：验证闭环

向被采集的日志文件追加一条新的异常日志，等待下一个采集周期（或手动点击采集）。异常会以新事件进入对应异常组，组上的累计次数增加；若满足告警阈值，Webhook 端会收到通知。至此，采集、解析、聚合、告警的完整链路已全部打通。

## 4. 日常使用指南

### 4.1 每天：从仪表盘与健康检查开始

仪表盘顶部是平台健康状态条，绿色表示采集链路正常；出现黄色或红色时，按提示进入系统健康页面查看。该页面提供堆内存、磁盘使用率、数据库体积、运行时长等资源水位，以及每个日志源的最近采集状态、下次调度时间、连续失败次数与调度延迟。磁盘使用率超过 70% 显示黄色、超过 85% 显示红色——这是日志平台最常见的故障来源，务必关注。

### 4.2 处理一个新异常的标准流程

1. 在异常分析页按待处理筛选，按严重程度与出现次数排序定位本次要处理的问题；
2. 打开详情页阅读消息模板与原始堆栈，参考内置知识库建议初步判断；
3. 点击 AI 根因分析（需先在系统设置启用 AI），获得结构化的根因与修复方案；
4. 在修复闭环表单中指派处理人、打上业务标签、填写修复说明，状态改为已分析或处理中；
5. 修复上线验证通过后，将状态改为已修复并留存说明。若修复后同指纹异常再次出现，组会自动重新打开。

### 4.3 发布前：创建静默窗口

计划内发布或处理已知故障期间，在告警页面的静默窗口标签下创建静默：目标可以是某个日志源（发布期间该源不再触发告警）或某个异常组（修复验证期免打扰），时长 1 至 24 小时并可填写原因。静默到点自动失效，也可提前结束。日志源列表与异常详情页会显示静默徽标，避免遗忘。

### 4.4 每周：生成运维报告

报告中心提供昨日日报与近 7 天周报，自动汇总异常事件数及环比、新增异常类型数、本期修复数、遗留待处理数、采集失败次数与 Top 异常清单。报告为纯文本格式，可直接复制到群聊，也可填写收件人通过邮件发送（需先在系统设置配置 SMTP）。

### 4.5 排障：用日志检索看原始日志

看到异常后需要回看原始日志时，使用日志检索页面：选择日志源、输入关键字，平台会在原始文件中全文搜索，并展示命中行前后各 N 行的上下文，关键字高亮显示。支持忽略大小写与按时间范围过滤；单个文件最多读取 32MB，超出部分会给出截断提示。

## 5. AI 能力接入（可选）

AI 能力为可选项，未启用时平台依靠内置知识库同样可以给出修复建议。启用后，异常详情页的 AI 根因分析按钮将把脱敏后的异常模板、业务代码位置与最近一次原始日志发送给大模型，返回包含问题概述、根因分析、修复方案、预防措施四个部分的结构化报告，并可一次批量分析最多 20 个待处理异常组。

| 服务商 | 接口地址（Base URL） | 模型示例 |
|---|---|---|
| OpenAI | https://api.openai.com/v1 | gpt-4o-mini |
| 智谱 GLM | https://open.bigmodel.cn/api/paas/v4 | glm-4-flash |
| DeepSeek | https://api.deepseek.com/v1 | deepseek-chat |
| Ollama 本地模型 | http://内网机器IP:11434/v1 | qwen2.5:14b |

启用步骤：进入系统设置，填入接口地址、模型名与 API Key，勾选启用后保存，点击测试 AI 连通验证。API Key 输入框留空表示保持原有密钥不变。对数据敏感的内网环境推荐使用 Ollama 等本地模型，日志内容不出内网。

## 6. 告警渠道与邮件配置

### 6.1 Webhook 报文说明

告警触发时，平台以 POST 方式向渠道地址发送 JSON 报文，包含 source、title、content、time、level 五个字段。企业微信、钉钉、飞书的机器人协议略有差异，建议在中间加一层转换网关，或使用群机器人提供的原生 Webhook 适配服务。

### 6.2 SMTP 邮件配置

在系统设置页面填写 SMTP 服务器地址、端口、用户名、密码或授权码与发件人，勾选 SSL（465 端口通常勾选，587 端口改用 STARTTLS 时取消勾选）。保存后可在告警页面右上角点击发测试邮件验证。告警规则中直接填写收件人即可按邮件通知，多个收件人用逗号分隔。

## 7. 系统健康与数据维护

### 7.1 采集失败的排查顺序

1. 系统健康页确认失败源与最近失败时间，点击其关联服务器的测试按钮复现问题；
2. SSH 类源依次检查：主机端口可达性、账号密码是否变更、账号对日志目录的读权限；
3. LOCAL 类源检查：路径是否存在、编码是否与文件一致、进程是否具备文件读权限；
4. 确认为计划内原因（停机维护）时，创建静默窗口避免告警误报，恢复后结束静默。

### 7.2 数据保留与备份

异常事件默认保留 30 天，可在系统设置调整；每日凌晨 3 点自动清理过期事件与 7 天前的采集审计记录。全量备份方法：停止平台进程后，复制运行目录下的 data 文件夹到安全位置，重启即完成恢复。H2 控制台（/h2-console）可用于日常数据核查，连接串 jdbc:h2:file:./data/logpilot，用户 sa，密码为空，生产环境建议在反代层屏蔽该路径。

### 7.3 操作审计

系统设置中维护操作人标识（默认 admin）后，服务器的增删与测试、日志源的增删与启停、异常状态流转、AI 分析、告警与静默配置变更、系统设置保存等关键操作都会写入审计日志。审计页面支持按操作人与动作关键字过滤，用于回答谁在什么时候改过什么。

## 8. 常见问题

**采集正常但异常分析里没有数据？**
首先确认日志文件中确实包含 ERROR、FATAL 或异常堆栈内容；其次检查解析格式：标准 logback/log4j2 格式用 AUTO，非标准格式改用 RAW 逐行模式；最后在异常事件页面按时间倒序确认事件是否入库。

**详情页或检索结果中文乱码？**
日志文件编码与日志源配置不一致所致。Windows 服务器常见 GBK 编码，在日志源的编码下拉框中改为 GBK 或 GB18030 后重新采集即可。

**启动时报 Port 18090 was already in use？**
端口被其他程序占用。以 `--server.port=18091` 参数启动换端口，或在 application.yml 中修改默认端口。

**AI 根因分析按钮是灰色的？**
AI 未启用或配置不完整。进入系统设置，确认已勾选启用且接口地址、API Key、模型三项均已填写，保存后按钮即恢复可用。也可先点击测试 AI 连通定位问题。

**SSH 服务器测试提示认证失败？**
依次核对用户名、密码是否正确，私钥格式是否为 PEM 且包含完整头尾行，私钥口令是否填在密码框；同时确认该账号未被 SSH 配置限制登录。提示连接超时则检查防火墙与安全组放行。

**健康页磁盘使用率告警或平台写入失败？**
磁盘剩余空间不足。优先清理被采集服务器上的过期日志与平台数据目录中的历史文件，并在系统设置中调小事件保留天数；长期方案是为磁盘扩容并建立 85% 使用率的外部监控。

**误删了日志源或数据如何恢复？**
日志源删除后历史异常数据仍保留，重新创建同名日志源不会影响既有异常组。数据库级别的恢复依赖第七章的 data 目录备份，请养成变更前备份的习惯。
